# Vaultwarden 网页管理面板 0.6.3

面向日常管理的表单面板：填写配置、点击部署、查看任务结果。常用功能不再要求输入脚本菜单编号。配置页面按组点击展开，默认只展开主要配置；收起时显示简短状态，未保存的表单值会保留，校验错误会自动展开对应分组。

## 安装与升级

在 Linux 服务器的交互式 SSH 会话中执行：

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/Oliver-LL/vw_web/main/vw-panel/install-vw-web.sh -o install-vw-web.sh && sudo bash install-vw-web.sh
```

首次运行先显示安装菜单：1 安装/升级面板、2 进入原始 Bash、3 面板管理、4 卸载面板、0 退出。端口直接回车随机选择空闲端口；密码直接回车生成 24 字符随机密码，自定义密码至少 12 字符。安装成功后终端集中显示地址、端口与密码，原文临时文件随后删除。升级执行同一条命令，保留面板密码、端口、域名和原部署数据。升级不随机重置已有端口和密码。新代码推送至公开仓库 `main` 分支后，下载地址才包含新版。

环境：Linux、systemd、Bash 4+、Python 3.9+（需支持 scrypt）、flock。缺少 Python 时安装器尝试使用 apt/dnf/yum 安装。面板不依赖 npm 或 pip，Docker 可在登录后通过概览页安装。

面板默认监听 `0.0.0.0`；访问 `http://服务器IP:端口`。云安全组与服务器防火墙需允许面板端口。公网使用建议配置 HTTPS 反代，面板以 root 身份执行管理操作，应只向管理员开放。

## 从零部署

1. 概览页如提示环境未就绪，点击“安装 Docker”。它使用 Docker 官方安装器，会修改服务器系统软件。
2. 打开“密码库配置”，填写密码库 HTTPS 地址和管理员邮箱。新服务器推荐自动 HTTPS；已有反向代理请选择对应方式。
3. 保存基本配置，设置并加密密码库管理口令，然后点击“部署 / 应用配置”。
4. 在“任务与日志”查看结果。自动 HTTPS 需要先解析域名，并确保 TCP 80 / 443 未被占用且可入站访问。
5. 打开密码库，创建首个账号，然后按需要关闭新用户注册。

服务器环境默认自动检测：发现明确的已有反代时建议复用，入口空闲时推荐新装；多个候选或无法确认时给出选择与原因。仍可手动指定新装或复用已有反代。新装服务均使用 Docker 部署：

- 自动安装 Caddy：无需预装反代，部署时启动独立 Caddy 容器并申请 HTTPS 证书；域名需指向本机，80 / 443 需放行且无冲突。
- 自动安装 NPM：创建管理账号，自动配置密码库站点与 HTTPS，后续证书由 NPM 自动续期。管理端口默认 8181，密码留空随机生成；保存后通过受登录和 CSRF 保护的按钮查看账号。
- 自动安装 Nginx：自动生成 HTTP 验证和 HTTPS 反代配置，使用 Certbot 申请证书；每 12 小时检查续期，Nginx 每 6 小时加载证书。申请或配置失败时恢复此前的 Nginx 配置。
- 已有宿主机反代：Vaultwarden 只映射 `127.0.0.1:8080`（端口可选），已有 Nginx、Caddy 等指向该地址并管理 HTTPS。不会安装宿主机反代。
- 已有容器反代：支持 NPM、Caddy、Traefik 等。检测运行中代理的实际自定义网络，只有一个可用网络时自动填入，多个网络时选择，也可手动填写。目标填 `http://vaultwarden:80`，密码库域名与 HTTPS 在现有反代中配置；不会自动安装 NPM 或改写已有代理站点。

面板域名和密码库域名相互独立。面板设置中允许一个域名，不会自动修改 DNS 或配置反向代理。

## 图形化功能

- 概览：密码库与备份容器状态、最近本机备份、首次部署引导。
- 密码库配置：域名、管理员邮箱、注册、邀请、Send、WebSocket、网页端、紧急访问、WAL、登录限流、会话时间、时区、管理口令和 Push 开启/删除。
- 邮件服务：SMTP 地址、端口、加密方式、发件邮箱、账号与授权码。
- 备份保护：预设或自定义 CRON、保留天数、时区、加密密码、启用/暂停、立即备份、升级备份容器与本机文件列表。
- 备份邮件：独立 SMTP 设置、成功/失败通知、会话聚合、关闭清理和测试邮件。
- 数据恢复：上传/下载 zip、7z，本机恢复、远程备份浏览下载、数据库校验、保留旧数据与失败回滚。兼容原备份镜像的 db.日期.sqlite3、config.日期.json 和嵌套 tar。仅支持原脚本默认的 SQLite 部署。
- 诊断：访问信息、系统状态、环境体检、备份远程投递检查和反代日志；日志支持定时刷新。
- 卸载清理：选择主服务/备份/全部，默认保留配置与数据；永久删除需勾选并输入 DELETE。恢复需输入 RESTORE。
- WebDAV：填写地址、账号、应用密码和目录，验证连接后切换目标。会创建远程目录；不搬迁或删除原备份。
- 任务：部署、停止、升级、备份、日志读取与失败原因。任务按钮调用独立后端接口，不自动回答 Bash 菜单。
- 面板设置：HTTPS 域名白名单及折叠的高级工具。

密码字段不回填。留空时保留原密码；首次设置备份密码和管理口令至少 12 字符。管理口令通过 Argon2id 哈希后保存，原文不写入任务输出或配置。

已有部署从 `~/.vw_deploy.conf` 读取目录与代理方式，不执行该文件。保存表单保留未修改的环境项、远程配置与其他配置键；修改环境文件前保留一份 `.panel-backup`。现有安装目录和代理拓扑不会通过表单重新生成。现有独立 Caddy 配置或带 VW_MANAGED 标记的站点可以在网页修改域名并同步配置；无法识别的共享站点拒绝覆盖。

新建备份默认在本机保存加密归档。已有远程目标在修改备份计划时保持原样。本机副本不能抵御服务器损坏；可连接 WebDAV 远程存储。远程存储页面使用 Rclone 官方非交互配置协议逐项生成表单，支持加载全部存储类型、重新配置/授权、验证连接、查询容量与身份、脱敏配置展示、删除配置和多目标目录。OAuth 仍需按服务商要求完成外部授权；向导会显示服务商提供的步骤，部分服务商可能要求在有浏览器的设备上取得授权结果，再回填隐藏输入。不会将令牌写入任务日志。

## 操作与日志

同一时间只执行一个任务或高级控制台，跨进程共享操作锁。原始脚本未加入此锁，切勿在另一 SSH 会话中同时执行部署或恢复。

表单保存与应用分开：保存不会立即重启容器，点击应用才生效。失败会显示真实命令错误；服务部署后检查容器运行状态，DNS 和 HTTPS 是否可用仍以实际访问为准。

后台任务在浏览器关闭后继续。任务状态只保存在当前面板进程，输出以权限 600 的临时文件保存在状态目录内，当前任务替换时清理前一任务输出；面板重启后状态清空，不提供完整操作审计。升级重启面板可能中断任务，应先完成当前操作。任务输出尽量遮蔽已知密码，服务自身输出仍仅供管理员查看。

原脚本高级工具是兼容入口：支持按行输入、回车、中断与隐藏输入，不是完整终端模拟器。

## 面板域名与 SSH 管理

```bash
sudo vwp               # 交互管理菜单
sudo vwp original      # 原始 Bash 脚本
sudo vwp bash          # 与网页共用锁的兼容分支
sudo vwp uninstall     # 只卸载面板，保留密码库和备份
sudo vwp info
sudo vwp status
sudo vwp logs
sudo vwp restart
sudo vwp password
sudo vwp port 8788
sudo vwp domain https://panel.example.com
```

域名需先配置 DNS，再将 Nginx / NPM / Caddy 的 HTTPS 反代指向面板。宿主机反代目标为 `http://127.0.0.1:面板端口`，容器中的 NPM 使用其可访问的宿主机 IP。保留浏览器原始 Host，包括非标准端口：`proxy_set_header Host $http_host;`。

## 终端卸载与安装菜单

`sudo vwp uninstall` 要求输入 `UNINSTALL`，停止并禁用面板服务，移除面板程序与终端命令；另行询问是否清除面板密码与域名设置，默认保留。它不移除密码库、Caddy、备份或 Docker。有网页任务运行时拒绝卸载。

同一安装文件支持 `--install`、`--original`、`--menu`、`--uninstall`；无参数时显示菜单。`--extract 目录` 仍只解包。

## 本地开发

本目录是面板开发目录，直接修改源码。打包不会覆盖 `vw_web.sh`。

- `web/static/`：原生 HTML、CSS、JavaScript。
- `web/server.py`：登录、会话、CSRF、HTTP 接口与旧控制台。
- `web/manager.py`：配置读取、校验、保留式写入、Docker 任务和锁。
- `web/operations.py`：完整运行参数、通知、多目标、Rclone 表单向导、诊断、恢复和服务卸载。
- `panel-cli.sh`：终端菜单、原始脚本入口和面板卸载。
- `web/tty_worker.py`：高级控制台 TTY。
- `installer-header.sh`：系统安装逻辑。
- `build.py`：打包本地代码，校验原始快照，生成单文件安装器。
- `install-vw-web.sh`：发布产物，修改源文件后重新生成并一同提交。
- `vw_original.sh`：原始脚本快照，不修改。
- `vw_web.sh`：兼容分支，保留原业务流程、网页锁与初始化调整，并支持读取表单写入的 dotenv 引号。

## 按实际状态展示提示

首次部署引导在配置完成且容器已存在后隐藏；运行中且没有待应用更改时，不持续显示“配置准备好了”或“首次部署”横幅。密码库与备份分别记录应用状态，未保存、已保存待应用、应用中、失败和服务停止使用不同提示。

状态记录在 `/var/lib/vw-panel/application.json`，仅记录配置指纹，不保存密码原文。应用成功后才更新；失败不会清除待应用提示。刷新页面和面板重启后仍可识别。旧部署没有记录时标为未知，不直接声称配置已应用；有运行中的容器时也不重复显示首次部署引导。

本机归档为空与远程备份缺失分开描述；备份已运行时不再提示“先启用”。Docker 未安装与服务不可连接分开处理，后者不显示重复安装按钮。已有面板域名不再显示新增域名的首次引导。

## 面板更新与终端菜单

登录后左下角版本号自动检查 GitHub `main` 分支发布的安装包；页面打开时定时读取检查结果，正常情况下每六小时重新向 GitHub 检查，也可点击版本号立即检查。网络失败会显示检查失败，不会冒充“已是最新”。

发现更新后点击“升级面板”。程序校验下载包的 SHA-256，由独立 systemd 任务执行后台升级，因此面板重启不会终止更新器。保留端口、密码和部署配置，不重启 Vaultwarden 或备份容器。现有操作未结束时拒绝升级；升级后自动重新连接并恢复未过期的登录。首次从 0.6.0 或更早版本升级，旧内存会话可能仍需重新登录一次。失败详情可查 `/var/lib/vw-panel/update.log`。此校验用于发现下载损坏或版本不一致，不是独立签名认证。真实 systemd 自升级仍需服务器验收。

终端只安装 `vwp`：

```bash
vwp                # 管理菜单（非 root 用户加 sudo）
vwp check-update   # 立即检查更新
vwp update         # 确认后后台升级面板
vwp bash           # 共享网页配置的 Bash 兼容菜单
vwp original       # 未修改的原始快照，进入前提示兼容差异
vwp uninstall      # 卸载面板，保留密码库与备份
```

网页与兼容 Bash 使用相同的 `/root/.vw_deploy.conf`、部署目录、环境文件与容器，能够读取已有配置。原始快照保持逐字不变，虽然能找到部署目录与容器，但不解析网页写入的部分 dotenv 引号，某些开关、域名或密码读取可能不准确，因此推荐兼容菜单。两者名称明确区分。

发布前运行 `python3 build.py`，把生成的 `install-vw-web.sh`、`release.json`、`version.json` 与代码一起提交。检测更新依据构建指纹，即使版本号未变，也能识别新的构建。旧版本首次需要手动升级到此版本，之后即可使用页面更新入口。

## 0.5.1 登录状态修复

刷新页面先展示中性连接状态，会话检查通过后直接进入面板；仅在服务器确认未登录时显示登录表单。网络异常显示重试入口，不误当作未登录。

重新登录或退出时，取消前一会话的后台请求并忽略迟到的响应，防止旧 401 将新登录踢回登录页，或旧配置结果覆盖当前页面。登录成功后再次校验浏览器会话，再展示工作区；Cookie 无法保持时在登录页说明原因。旧版重装/重启会使内存会话失效；0.6.1 起未过期会话会保存在面板状态目录，后续升级可恢复登录。

浏览器回归检查包含慢速刷新、并发 401、旧更新检查 401 迟到、旧配置 200 迟到、重装后的登录、断线重试、Cookie 被拒绝与错误密码恢复。

## 0.5.2 版本弹窗

点击左下角版本号，查看当前版本、最新版本和更新状态，有更新时可选择“立即更新”。右上角刷新图标立即检查，下方打开更新日志。后台检查不主动展开弹窗。支持点击外部或 Escape 关闭，手机屏幕自动调整弹窗位置。

## 0.5.3 登录后的认证错误处理

已登录页面收到认证错误时，先重新核验当前会话。会话有效时最多重试一次读取；保存配置、启动任务等写入请求不会自动重复提交。确实失效时返回登录表单，不在工作区显示“请先登录”的错误横幅。迟到的同类提示也会核验当前会话再处理。

浏览器模拟接口回归覆盖“刷新 → 登录 → 迟到提示”、单次 401、状态码 200 的认证错误消息、写入不重放，以及真实会话失效的处理。用户服务器上的具体触发来源仍需部署后验证。

## 0.5.4 版本检查反馈

点击版本号立即打开弹窗，无论检查结果是否有新版本都显示当前状态。请求超过 20 秒会停止转圈并提示重试；连接失败不会显示旧结果的升级按钮。浏览器回归使用真实鼠标点击，并验证慢速响应、失败、超时与重试恢复。

## 0.5.5 版本卡片原生展开

版本入口改用浏览器原生 details/summary 展开，卡片显示不依赖更新检查完成；检查中仍可展开与收起。移除打开时的自动焦点跳转和失焦关闭，保留点击外部与 Esc 关闭。页面的脚本和样式 URL 带版本号，保证新页面请求对应资源。

回归检查增加暂停页面脚本后的真实鼠标点击，验证卡片仍能展开并显示内容；网络失败、20 秒超时与重试检查继续覆盖。用户浏览器上“仅鼠标转圈”的具体触发原因尚未复现，部署后仍需验证。

## 0.5.6 反代与网络检测

基本信息明确区分自动安装 Caddy、已有宿主机反代、已有容器反代。首次配置时读取代理容器和网络，提供“重新检测”；检测不完整或代理停止时不自动填入网络，手动输入不会被重新检测覆盖。已有部署的网络与访问方式保持原值。Docker 尚未安装时说明先在运行概览安装 Docker，新服务器无需另外安装 Caddy 软件包。

外部反代网络在保存和部署时均校验存在及可接入性，部署不会自动创建一个与 NPM 无关的同名空网络。新装 Caddy 前检查宿主机端口、Docker 已发布端口及已有 caddy 容器，发生冲突时在写入配置前说明原因。现有共享反代的站点仍由其自身配置管理；与原脚本自动写入已有 Caddy 站点的流程不同，新接入已有 Caddy 时使用对应的宿主机或容器反代方式。

测试使用模拟 Docker 信息验证网络读取、冲突保护和已删除网络的拒绝；本地浏览器验证单网络填入、多网络选择、手动值保留、停止代理和检测失败。真实 VPS 的 Docker / NPM / Caddy 联通及证书申请仍需部署验收。原始脚本快照保持不变。

本机自带 Bash 3.2，完整打包检查中的原 Bash 菜单用例未通过（脚本要求 Bash 4+）；安装包内容比对和损坏包拒绝检查已通过，原 Bash 源码未作修改。

## 0.6.0 新服务器反代安装

“服务器环境”先选择“新服务器 · 安装反代”或“已有反代 · 直接接入”。新装可选择 Caddy、Nginx Proxy Manager、Nginx。已有部署继续保留原来的目录、网络与代理类型。安装 NPM / Nginx 需要有效邮箱、域名解析和可访问的 80 / 443 端口；Docker 尚未安装时先在运行概览安装。

NPM 使用固定的官方 2.16.0 镜像，SQLite 数据与证书位于部署根目录的 npm 子目录。随机管理密码存放在权限 0600 的私有文件；普通配置接口不返回密码，任务日志隐藏已知密码和 NPM 初始化密码行。管理端口只在首次配置时选择，管理账号可在保存后查看；更改 NPM 自身密码后，在网页填写当前密码以同步面板的 API 登录信息。应用配置通过本机 NPM API 申请证书并创建或更新记录在案的密码库站点，不改写其他站点；新域名与未记录的已有站点冲突时拒绝覆盖。

Nginx 使用官方 stable-alpine 镜像，Certbot 使用官方镜像；配置与证书位于部署根目录的 nginx 子目录。首次部署先启动 HTTP 验证站点，成功取得证书后校验并加载 HTTPS 配置，再启用后台续期。续期不挂载 Docker socket，Nginx 定时加载续期后的证书。密码库域名更改后，保存只修改待应用的配置，应用失败恢复原有活动配置。

卸载密码库默认保留新装的 NPM / Nginx，避免影响其他站点。需要同时移除时明确勾选选项；选择删除数据会同时删除所选反代的账号、站点和证书，保留数据时可通过重新部署恢复。原始 Bash 快照未修改；它仍按容器反代方式读取这些部署的网络，新装 NPM / Nginx 的自动建站、证书和管理账号功能请使用网页完成。

参考官方资料：[NPM 部署](https://nginxproxymanager.com/setup/)、[初始化管理账号](https://nginxproxymanager.com/advanced-config/)、[NPM 2.16.0 接口定义](https://github.com/NginxProxyManager/nginx-proxy-manager/tree/v2.16.0/backend/schema/paths/nginx)、[Certbot webroot 与续期](https://eff-certbot.readthedocs.io/en/stable/using.html)、[Nginx WebSocket 反代](https://nginx.org/en/docs/http/websocket.html)。

验证包括模拟 Docker 的部署与回滚测试、本地 HTTP 服务验证 NPM 请求和凭据保护、真实 Docker Compose 配置解析及浏览器桌面/移动端回归。未在真实 VPS 运行新容器或完成公网证书签发；这些外部步骤仍需部署验收。本机 Bash 3.2 无法通过要求 Bash 4+ 的原脚本菜单用例。

## 0.6.1 实际日志来源、升级登录和自动环境建议

代理日志使用当前部署记录、Docker 网络和实际发现的容器 / 宿主机服务确定来源，不再回退到名为 caddy 的容器。诊断页显示来源名称，多个候选时选择，并支持重新检测；没有可识别服务时说明原因。宿主机 Nginx 优先读取常见日志文件，其余宿主机服务读取对应 systemd 日志；检测基于 ss 监听进程名。自定义服务名或非标准日志路径可能需要手动确认。

配置页默认“自动检测 · 推荐”。唯一且可接入的已有反代自动选用相应接入方式与网络；入口空闲时推荐 Caddy，仍可改选 NPM、Nginx。有多个候选、停止的服务、网络不可接入或入口占用不明时，不静默创建新代理，展示选择和处理原因。手动选择保留，旧检测请求不会覆盖新配置的结果。

有效登录会话持久化到 /var/lib/vw-panel/sessions.json，权限 0600，仅保存会话标识的哈希、CSRF、原始创建时间和密码凭据指纹，不保存面板明文密码或原始 Cookie 标识。有效期保持 12 小时，数量限制 32；升级不延长有效期。主动退出会持久撤销当前会话，重置面板密码会使旧会话失效。

点击升级后，页面等待服务恢复并在构建更新后重新加载，Cookie 有效时自动回到工作区。网络短暂中断不会作为工作区错误反复展示。迁移说明：0.6.0 及更早版本未写入会话文件，首次升级到本版仍可能需要登录一次；建立新会话后，后续升级和重启可恢复。

新增测试覆盖实际反代日志、宿主机识别、多个候选、端口占用未知时不自动安装、手动选择保留、旧检测响应隔离、会话重启恢复 / 到期 / 退出 / 密码重置，以及真实 HTTP 服务重启后的 Cookie 与 CSRF。浏览器回归验证自动环境选择、来源标签和升级后恢复工作区。Linux 上的实际服务发现与真实 systemd 升级仍需部署验收。原始 Bash 快照保持不变。

## 0.6.2 检测结果直接选中服务器环境

首次填写时，检测到可用反代后，服务器环境直接选中“使用已有反代”，并显示已选中的接入类型与网络；入口空闲时选中“安装新的反代”，无法确认时保留检测待确认状态。后台仍自动跟随检测结果，用户手动调整服务器环境、反代软件或接入类型后保留其选择。已保存的面板管理反代显示当前配置名称，避免显示为待安装的新服务器。浏览器回归覆盖实际选中项、手动调整保留和移动布局。

## 0.6.3 精简检测展示与升级后刷新

自动检测成功后，服务器环境直接显示“使用已有反代（检测到 NPM）”等结果，或“安装新的反代（未检测到反代）”。正常结果不再占用独立提示栏；重新检测入口移到字段旁。多候选的选择控件位于表单中，只有需要选择或检测不明确时展示说明。

页面记录首次加载到的构建标识，与服务器后续返回的安装构建比较，构建更新后整页刷新一次，不再依赖升级中标记。保留已确认的升级目标，旧空闲状态响应不会提前终止等待；新页面不会因成功状态继续保留而反复刷新。有效登录沿用已有会话。

浏览器回归统计真实主文档导航次数，验证只刷新一次、升级标记提前清除仍能刷新、无刷新循环和登录保留，同时验证内联检测与移动布局。修复前已打开的旧页面需先加载新脚本；本次升级后若仍未自动刷新，可手动刷新一次，后续使用新逻辑。
