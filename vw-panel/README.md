# Vaultwarden 网页管理面板 0.5.1

面向日常管理的表单面板：填写配置、点击部署、查看任务结果。常用功能不再要求输入脚本菜单编号。配置页面按组点击展开，默认只展开主要配置；收起时显示简短状态，未保存的表单值会保留，校验错误会自动展开对应分组。

## 安装与升级

在 Linux 服务器的交互式 SSH 会话中执行：

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/Oliver-LL/vw_web/main/vw-panel/install-vw-web.sh -o install-vw-web.sh && sudo bash install-vw-web.sh
```

首次运行先显示安装菜单：1 安装/升级面板、2 进入原始 Bash、3 面板管理、4 卸载面板、0 退出。端口直接回车随机选择空闲端口；密码直接回车生成 24 字符随机密码，自定义密码至少 12 字符。安装成功后终端集中显示地址、端口与密码，原文临时文件随后删除。升级执行同一条命令，保留面板密码、端口、域名和原部署数据。升级不随机重置已有端口和密码。新代码推送至公开仓库 `main` 分支后，下载地址才包含新版。

环境：Linux、systemd、Bash 4+、Python 3.9+（需支持 scrypt）、flock。缺少 Python 时安装器尝试使用 apt/dnf/yum 安装。面板不依赖 npm 或 pip，Docker 可在登录后通过概览页安装。

面板默认监听 `0.0.0.0`；访问 `http://服务器IP:端口`。云安全组与服务器防火墙需允许面板端口。公网使用建议配置 HTTPS 反代，面板以 root 身份执行管理操作，应只向管理员开放。

## 从零部署

1. 概览页如提示环境未就绪，点击“安装 Docker”。它使用 Docker 官方安装器，会修改服务器系统软件。
2. 打开“密码库配置”，填写密码库 HTTPS 地址和管理员邮箱。新服务器推荐自动 HTTPS；已有反向代理请选择对应方式。
3. 保存基本配置，设置并加密密码库管理口令，然后点击“部署 / 应用配置”。
4. 在“任务与日志”查看结果。自动 HTTPS 需要先解析域名，并确保 TCP 80 / 443 未被占用且可入站访问。
5. 打开密码库，创建首个账号，然后按需要关闭新用户注册。

三种访问方式：

- 自动 HTTPS：生成独立 Caddy 配置并申请证书。
- 宿主机反代：Vaultwarden 只映射 `127.0.0.1:8080`（端口可选），宿主机 Nginx 指向该地址。
- 容器反代：选择与 NPM 相同的 Docker 网络，目标填 `http://vaultwarden:80`，并配置密码库域名的 HTTPS。

面板域名和密码库域名相互独立。面板设置中允许一个域名，不会自动修改 DNS 或配置反向代理。

## 图形化功能

- 概览：密码库与备份容器状态、最近本机备份、首次部署引导。
- 密码库配置：域名、管理员邮箱、注册、邀请、Send、WebSocket、网页端、紧急访问、WAL、登录限流、会话时间、时区、管理口令和 Push 开启/删除。
- 邮件服务：SMTP 地址、端口、加密方式、发件邮箱、账号与授权码。
- 备份保护：预设或自定义 CRON、保留天数、时区、加密密码、启用/暂停、立即备份、升级备份容器与本机文件列表。
- 备份邮件：独立 SMTP 设置、成功/失败通知、会话聚合、关闭清理和测试邮件。
- 数据恢复：上传/下载 zip、7z，本机恢复、远程备份浏览下载、数据库校验、保留旧数据与失败回滚。兼容原备份镜像的 db.日期.sqlite3、config.日期.json 和嵌套 tar。仅支持原脚本默认的 SQLite 部署。
- 诊断：访问信息、系统状态、环境体检、备份远程投递检查和 Caddy 日志；日志支持定时刷新。
- 卸载清理：选择主服务/备份/全部，默认保留配置与数据；永久删除需勾选并输入 DELETE。恢复需输入 RESTORE。
- WebDAV：填写地址、账号、应用密码和目录，验证连接后切换目标。会创建远程目录；不搬迁或删除原备份。
- 任务：部署、停止、升级、备份、日志读取与失败原因。任务按钮调用独立后端接口，不自动回答 Bash 菜单。
- 面板设置：HTTPS 域名白名单及折叠的高级工具。

密码字段不回填。留空时保留原密码；首次设置备份密码和管理口令至少 12 字符。管理口令通过 Argon2id 哈希后保存，原文不写入任务输出或配置。

已有部署从 `~/.vw_deploy.conf` 读取目录与代理方式，不执行该文件。保存表单保留未修改的环境项、远程配置与其他配置键；修改环境文件前保留一份 `.panel-backup`。现有安装目录和代理拓扑不会通过表单重新生成。现有独立 Caddy 配置或带 VW_MANAGED 标记的站点可以在网页修改域名并同步配置；无法识别的共享站点拒绝覆盖。

新建备份默认在本机保存加密归档。已有远程目标在修改备份计划时保持原样。本机副本不能抵御服务器损坏；可连接 WebDAV 远程存储。远程存储页面使用 Rclone 官方非交互配置协议逐项生成表单，支持加载全部存储类型、重新配置/授权、验证连接、查询容量与身份、脱敏配置展示、删除配置和多目标目录。OAuth 仍需按服务商要求完成外部授权；向导会显示服务商提供的步骤，部分服务商可能要求在有浏览器的设备上取得授权结果，再回填隐藏输入。不会将令牌写入任务日志。

## 操作与日志

同一时间只执行一个任务或高级控制台，跨进程共享操作锁。原始脚本未加入此锁，切勿在另一 SSH 会话中同时执行部署或恢复。

表单保存与应用分开：保存不会立即重启容器，点击应用才生效。失败会显示真实命令错误；服务部署后检查容器运行状态，DNS 和 HTTPS 是否可用仍以实际访问为准。

后台任务在浏览器关闭后继续。任务状态只保存在当前面板进程，输出以权限 600 的临时文件保存在状态目录内，当前任务替换时清理前一任务输出；面板重启后状态清空，不提供完整操作审计。升级重启面板可能中断任务，应先完成当前操作。任务输出尽量遮蔽已知密码，服务自身输出仍仅供管理员查看。

原脚本高级工具是兼容入口：支持按行输入、回车、中断与隐藏输入，不是完整终端模拟器。

## 面板域名与 SSH 管理

```bash
sudo vwp               # 交互管理菜单
sudo vwp original      # 原始 Bash 脚本
sudo vwp bash          # 与网页共用锁的兼容分支
sudo vwp uninstall     # 只卸载面板，保留密码库和备份
sudo vwp info
sudo vwp status
sudo vwp logs
sudo vwp restart
sudo vwp password
sudo vwp port 8788
sudo vwp domain https://panel.example.com
```

域名需先配置 DNS，再将 Nginx / NPM / Caddy 的 HTTPS 反代指向面板。宿主机反代目标为 `http://127.0.0.1:面板端口`，容器中的 NPM 使用其可访问的宿主机 IP。保留浏览器原始 Host，包括非标准端口：`proxy_set_header Host $http_host;`。

## 终端卸载与安装菜单

`sudo vwp uninstall` 要求输入 `UNINSTALL`，停止并禁用面板服务，移除面板程序与终端命令；另行询问是否清除面板密码与域名设置，默认保留。它不移除密码库、Caddy、备份或 Docker。有网页任务运行时拒绝卸载。

同一安装文件支持 `--install`、`--original`、`--menu`、`--uninstall`；无参数时显示菜单。`--extract 目录` 仍只解包。

## 本地开发

本目录是面板开发目录，直接修改源码。打包不会覆盖 `vw_web.sh`。

- `web/static/`：原生 HTML、CSS、JavaScript。
- `web/server.py`：登录、会话、CSRF、HTTP 接口与旧控制台。
- `web/manager.py`：配置读取、校验、保留式写入、Docker 任务和锁。
- `web/operations.py`：完整运行参数、通知、多目标、Rclone 表单向导、诊断、恢复和服务卸载。
- `panel-cli.sh`：终端菜单、原始脚本入口和面板卸载。
- `web/tty_worker.py`：高级控制台 TTY。
- `installer-header.sh`：系统安装逻辑。
- `build.py`：打包本地代码，校验原始快照，生成单文件安装器。
- `install-vw-web.sh`：发布产物，修改源文件后重新生成并一同提交。
- `vw_original.sh`：原始脚本快照，不修改。
- `vw_web.sh`：兼容分支，保留原业务流程、网页锁与初始化调整，并支持读取表单写入的 dotenv 引号。

原始快照 SHA-256：`756b783a388b087ff48af8db93273543a2ea2ea7009bdcfd50201e671d044aff`。原始来源为 [上游 Gist](https://gist.githubusercontent.com/Oliver-LL/72ef2f0aa06ce5d4f186bbc67adebada/raw/gistfile1.txt)，安装与打包不重新下载上游。

## 按实际状态展示提示

首次部署引导在配置完成且容器已存在后隐藏；运行中且没有待应用更改时，不持续显示“配置准备好了”或“首次部署”横幅。密码库与备份分别记录应用状态，未保存、已保存待应用、应用中、失败和服务停止使用不同提示。

状态记录在 `/var/lib/vw-panel/application.json`，仅记录配置指纹，不保存密码原文。应用成功后才更新；失败不会清除待应用提示。刷新页面和面板重启后仍可识别。旧部署没有记录时标为未知，不直接声称配置已应用；有运行中的容器时也不重复显示首次部署引导。

本机归档为空与远程备份缺失分开描述；备份已运行时不再提示“先启用”。Docker 未安装与服务不可连接分开处理，后者不显示重复安装按钮。已有面板域名不再显示新增域名的首次引导。

## 面板更新与终端菜单

登录后左下角版本号自动检查 GitHub `main` 分支发布的安装包；页面打开时定时读取检查结果，正常情况下每六小时重新向 GitHub 检查，也可点击版本号立即检查。网络失败会显示检查失败，不会冒充“已是最新”。

发现更新后点击“升级面板”。程序校验下载包的 SHA-256，由独立 systemd 任务执行后台升级，因此面板重启不会终止更新器。保留端口、密码和部署配置，不重启 Vaultwarden 或备份容器。现有操作未结束时拒绝升级；升级后需要重新登录。失败详情可查 `/var/lib/vw-panel/update.log`。此校验用于发现下载损坏或版本不一致，不是独立签名认证。真实 systemd 自升级仍需服务器验收。

终端只安装 `vwp`：

```bash
vwp                # 管理菜单（非 root 用户加 sudo）
vwp check-update   # 立即检查更新
vwp update         # 确认后后台升级面板
vwp bash           # 共享网页配置的 Bash 兼容菜单
vwp original       # 未修改的原始快照，进入前提示兼容差异
vwp uninstall      # 卸载面板，保留密码库与备份
```

网页与兼容 Bash 使用相同的 `/root/.vw_deploy.conf`、部署目录、环境文件与容器，能够读取已有配置。原始快照保持逐字不变，虽然能找到部署目录与容器，但不解析网页写入的部分 dotenv 引号，某些开关、域名或密码读取可能不准确，因此推荐兼容菜单。两者名称明确区分。

发布前运行 `python3 build.py`，把生成的 `install-vw-web.sh`、`release.json`、`version.json` 与代码一起提交。检测更新依据构建指纹，即使版本号未变，也能识别新的构建。旧版本首次需要手动升级到此版本，之后即可使用页面更新入口。

## 0.5.1 登录状态修复

刷新页面先展示中性连接状态，会话检查通过后直接进入面板；仅在服务器确认未登录时显示登录表单。网络异常显示重试入口，不误当作未登录。

重新登录或退出时，取消前一会话的后台请求并忽略迟到的响应，防止旧 401 将新登录踢回登录页，或旧配置结果覆盖当前页面。登录成功后再次校验浏览器会话，再展示工作区；Cookie 无法保持时在登录页说明原因。重装/重启面板仍会使内存中的旧会话失效，因此需要重新登录一次。

浏览器回归检查包含慢速刷新、并发 401、旧更新检查 401 迟到、旧配置 200 迟到、重装后的登录、断线重试、Cookie 被拒绝与错误密码恢复。
