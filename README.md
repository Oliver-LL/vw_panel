# Vaultwarden 网页管理面板

在 Linux 服务器的交互式 SSH 会话中执行：

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/Oliver-LL/vw_web/main/vw-panel/install-vw-web.sh -o install-vw-web.sh && sudo bash install-vw-web.sh
```

需要 Linux、systemd 和 Bash 4+；缺少 Python 时安装器会尝试安装。按提示设置端口和管理员密码后，通过服务器 IP 访问面板。安装器默认监听 `0.0.0.0`，需自行配置安全组、防火墙和 HTTPS 反代。

升级也执行同一条命令，保留管理员密码、面板端口和域名设置。升级会重启面板，请先完成正在运行的控制台操作。

## 0.3 · 表单管理面板

密码库、注册权限、邮件与备份改为原生表单；部署、升级和备份通过后台任务执行，显示真实结果。支持 WebDAV 连接验证，保留旧部署与未修改的密码。原脚本控制台默认折叠，仅用于高级维护。

## 0.4 更新

支持原脚本 18 个主功能的独立网页操作，包括云盘向导、多目标备份、Push、通知、诊断、恢复与按范围卸载。宽屏页面随窗口展开。安装时端口/密码回车随机生成，成功后显示；升级保留已有配置。

终端执行 `sudo vwp` 打开管理菜单，`sudo vwp original` 进入原始脚本，`sudo vwp uninstall` 仅卸载面板并保留密码库和备份。安装文件无参数时显示安装/升级、原始脚本、管理和卸载菜单。

## 0.5.0 更新

左下角版本号自动检查面板构建，可点击升级。升级器独立运行并校验下载包，保留端口、密码及密码库配置；重启后重新登录。首次需先用安装命令升级到本版。

终端菜单使用 `vwp`，不安装 `vmp` 别名。`vwp bash` 为共享网页配置的兼容菜单；`vwp original` 是未修改的原始快照，进入前会说明配置格式差异。

发布前运行 `python3 vw-panel/build.py`，将生成的 `install-vw-web.sh`、`version.json`、`release.json` 与代码一并提交。

## 0.5.1 修复

刷新页面先检查会话，不再闪现登录页。重新登录时取消旧请求并忽略迟到的响应，避免旧会话的 401 打断新登录。网络异常显示重试入口；重装或重启面板后仍需重新登录一次。发布安装包和更新元数据已同步。

## 0.5.2

点击左下角版本号打开版本弹窗，查看当前与最新版本，选择立即更新，或查看更新日志。自动检查只更新圆点提示，不主动展开弹窗。

## 0.5.3

登录后收到认证错误时重新核验当前会话，有效时重试一次读取；写入操作不会自动重复。确实失效返回登录页。已增加刷新后重新登录的浏览器回归检查，服务器触发来源仍需部署后验证。

## 0.5.4

点击版本号立即显示检查状态。检查超过 20 秒会停止转圈并提示重试；检查失败时不会使用旧结果显示升级按钮。

## 0.5.5

版本卡片改用浏览器原生展开，显示卡片不依赖更新检查完成。移除自动焦点跳转和失焦关闭，保留外部点击与 Esc 关闭。页面资源地址带版本号，新增暂停脚本后的点击展开检查。

## 0.5.6

访问方式明确区分自动安装 Caddy、已有宿主机反代与已有容器反代。检测 NPM、Caddy 等代理实际使用的 Docker 网络，单网络自动填入，多网络选择，保留手动值。新装 Caddy 前检查端口冲突；外部反代网络保存和部署前校验，不创建无关的隔离网络。现有反代的域名和 HTTPS 仍由其自身配置。

## 0.6.0

新服务器可选择自动安装 Caddy、NPM 或 Nginx，也可直接接入已有反代。NPM 自动创建管理账号、配置密码库站点与 HTTPS；Nginx 自动配置 HTTPS、证书续期和加载，失败恢复旧配置。管理账号通过登录后的页面查看，卸载密码库默认保留反代，可明确选择同时移除。新服务通过 Docker 部署；真实 VPS 的容器启动与公网证书签发仍需验收。

## 0.6.1

服务器环境默认自动检测并给出复用或新装建议，多个候选时明确选择。代理日志按实际容器或宿主机服务读取，不再默认查找 Caddy。有效登录跨升级重启保留，升级后自动重连；首次从旧版迁移仍可能需要登录一次，主动退出、到期或重置密码会撤销登录。

## 0.6.2

首次填写时，服务器环境直接选中实际检测结果：已有反代默认“使用已有反代”，入口空闲默认“安装新的反代”，无法确认时等待检测或选择。手动调整反代软件和接入类型后保留选择；已保存的面板管理反代显示当前配置名称。

## 0.6.3

正常检测结果收进服务器环境选项括号，重新检测按钮移至字段旁，只有需确认时展示说明。升级完成按页面实际加载构建与服务端构建的差异刷新一次，保留有效登录，避免旧状态提前结束等待与循环刷新。浏览器验证了真实文档导航次数与移动布局。

## 0.6.4

统一各配置组的保存位置：展开后在组内右下角保存，收起时一起隐藏。基本信息和注册权限合并保存，其他独立设置保留各自保存入口。

## 0.6.5

备份操作统一收进顶部服务状态卡，暂停和升级可展开“服务维护”使用。

## 0.6.6 合并备份与恢复

侧栏统一使用“备份与恢复”，自动备份配置、文件下载、导入与恢复集中在同一页面。恢复表单默认折叠；在本机文件列表点击“选择恢复”，或上传备份后，可展开并填写恢复确认。旧恢复链接仍可打开正确位置。

## 0.6.7 日志操作整理

日志控件集中在任务卡片内。选择服务后点击“查看日志”，可开启每 5 秒自动刷新；日志结果自动展开。

## 0.6.8 推送凭据按需显示

启用官方推送后才显示 Installation ID、Installation Key 和获取说明，可点击链接前往 Bitwarden 官方申请页面。关闭开关不会清空未保存输入，保存关闭时仍按原逻辑移除配置。

## 0.6.9 卸载交互简化

网页卸载无需输入 DELETE，选择服务范围和数据处理方式后点击确认。默认保留配置与数据，永久删除仅影响所选服务；确认提示显示具体影响范围。
